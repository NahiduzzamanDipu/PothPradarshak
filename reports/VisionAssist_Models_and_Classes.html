No model performs navigation. Deciding which obstacle matters and whether to speak is a deterministic rule engine, not a network. It needs no training data, fails in ways that can be enumerated in advance, and can be defended line by line in a viva — all three of which matter more than sophistication in assistive software.

2. The nine trained classes

These are the classes the thesis model was actually trained on. The list was fixed before annotation began and never reordered, because the class index is baked into every label file: reordering would silently relabel the whole dataset.

The rule that produced this list: every class must map to an action the navigation layer can express in a sentence. Nothing decorative was included. A footpath contains hundreds of nameable things — shop signs, litter, parked bicycles' shadows — but a blind pedestrian only needs the ones that change where the next step goes.

5open_drainখোলা ড্রেন Uncovered drains, missing or displaced manhole covers The most dangerous class in the set: a fall into an open drain is a serious injury, and covers go missing often enough in Dhaka that this is routine, not hypothetical.

Read this table before quoting any class result. Per-class AP tracks instance count almost monotonically, which says the binding constraint is annotation coverage — not model capacity and not training length.

* stairs at 0.995 is computed over two test boxes. That is statistical noise. pothole and open_drain show zero recall: the model predicts neither class at all, and their precision of 1.000 is the convention used when no positive prediction was ever made, not a sign of quality.

The consequence must be stated plainly: the system is reliable on people and vehicles and is blind to the three fall hazards that motivated the class list. Section 5 explains why those classes were starved of data.

3.1 The two rules that keep the fusion honest

frame ──┬─▶ thesis best.pt  (9 classes)  ─────────────┐
        │                                             │
        └─▶ COCO yolo11n ──▶ keep ONLY the 12 above ──┤
                                                      ▼
                                          overlap > 0.55 IoU ?
                                          yes ─▶ drop the COCO box
                                          no  ─▶ keep it
  1. The indoor model is excluded from every class the thesis model covers — notably person, which both can detect. Without this the same pedestrian would be listed and announced twice.
  2. On any overlap above 0.55 IoU the thesis model wins, because it is the model trained on this thesis's data.

Declare this in the defence. These twelve classes are COCO-pretrained and carry no thesis-measured mAP. They are a deployment convenience, not a research contribution.

door is deliberately absent. COCO has no door class and the thesis dataset has no door annotations, so supporting it would mean inventing a capability that was never measured.

4. How the classes are ranked

Not every class carries equal weight. The navigation engine sorts detections by a score whose terms are readable rather than tuned, so any ordering can be explained.

TierScoreClassesReasoning
DANGER+100 pothole open_drain stairs curb pole car bus truck motorcycle bicycle train Fall or vehicle-collision hazards. A mistake here injures.
INDOOR+40 The twelve furniture classes of §3 Worth announcing, but walking into a chair is not walking into an open drain.
OTHER0 person, tree, street_obstacle, parked_vehicle and remaining COCO classes Announced on geometry alone. A person is usually avoidable and often moves.
Geometry CENTER +50  ·  NEAR +30 / MEDIUM +12 / FAR 0  ·  confidence × 10 Position and proximity dominate confidence, so the detector's certainty can never outrank being directly in the path.

A further 31 COCO classes are permanently ignored and never announced — food, sports equipment, small handheld items such as toothbrush, book and cell phone. They are real detections but nothing a pedestrian navigates around, and narrating them would bury the warnings that matter.

5. Prompts used to annotate each class

YOLO-World was driven with several descriptive phrases per class rather than the bare class name; open-vocabulary detectors respond markedly better to a description than to a label, and several phrasings recover objects any single phrasing misses. Thirty-five prompts map back onto the nine classes.

This table is the root cause of the failures in §2.1. Three classes — pothole, open_drain and curb — are flagged in the code as LOW_TRUST because the annotation model cannot find them.

A pothole has no consistent visual prototype: it is defined by the absence of intact surface, not by a characteristic shape, and is easily confused with a shadow, a repair patch or an ordinary paving seam. The open-vocabulary model therefore proposed almost no candidates, the human review had almost nothing to confirm, and those classes reached training with 12–17 instances.

The fix is annotation, not architecture: hand-draw 100–200 instances of each hazard class and retrain. The images already exist in the unused pool.

6. Summary

QuestionAnswer
How many models run at inference? Two detectors (thesis best.pt + COCO yolo11n.pt) and one text-to-speech voice per language.
How many classes can be detected? 21 — 9 trained on thesis data, 12 borrowed from COCO.
How many are thesis contributions? 9. Only these carry measured mAP.
How many work reliably today? 2 (person, parked_vehicle). Four are weak, three are not detected at all.
Which model is not in the running system? yolov8x-worldv2.pt — annotation only, offline.
Which component uses no model? Navigation, spatial reasoning and sentence generation — all deterministic rules.
